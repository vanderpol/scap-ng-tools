## Mandatory conversion semantics

- Convert SCAP 1.4 source Benchmark/Rule and standalone OVAL 5.12.3 to native SCAP-NG 0.4.1, preserving source XML/check/Definition/Test IDs, dependencies and provenance. Original Rule policy and Assessment testing are separate. Prefer automated OVAL when OVAL+OCIL coexist, retaining OCIL as nondefault manual alternative. OCIL-only Rules -> manual Assessment. Four SQLEXT-dependent SQL benchmarks' 209 Rules remain excluded by owner decision. Obsolete source constructs do not become fake native equivalents or disappear silently.
- Current PR #62 reports **8,892 source Rules; 6,732 converted/unverified; 507 blocked; 1,653 manual-only**. These are authoring/conversion counts, not scanner or SCC equivalence. Record independently validated outputs, semantic holds and all blocked reasons separately. Reconcile versioned old/new ledger and never promote schema validity into runtime proof.
- Preserve actual Variables, ordered multivalues, nested `concat`, `unique`, `merge`, `count` and source object/field references; no declaration-level datatype in approved native Variables, no coercion of numeric-looking source strings. Source expressions `foreach`, `else_if`, `values`, `regex_capture`, Set/Filter and arithmetic/legacy forms must map only when approved native semantics truly cover them; else explicit hold with source pointers. Do not silently discard entire source Tests or replace source collection with manual procedure without review.
- Real **CPE/platform applicability and shared applicability Assessments** must be converted as executable authored resources and correctly referenced by Rules/Benchmarks; no empty catalogs or hardcoded fixtures claimed as working. Profiles: Rules enabled by default, allow profile disable/re-enable. Preserve remediation, original Rule XML, input bindings, manual responses and publisher metadata.
- Full-65 corpus generation must be a **deterministic runnable script**, not repeated long AI editing sessions. Pin source ZIP/SHA and exact canonical converter/pack revisions; repeat generation and compare hashes. Large artifacts belong in evidence/Actions artifacts, not bloated commits. Validate JSON/YAML and produce per-Benchmark reproducibility receipts. Never silently update production content because schema changed.
- Maintain a clean audit of source->native edge cases and independent source test expectations (e.g. 0.3 304-vector historical evidence where relevant, without importing 0.3 grammar). Changed canon requires coordinated docs/metadata/pins, not a converter-only workaround.

## Boundaries, delivery and proof

`scap-ng` owns normative 0.4.1 schemas/semantics, `scap-ng-tools` conversion, `scap-ng-ri` scanner/collector/scale, `scap-ng-vscode` YAML-preserving authoring. Do not mutate another repo, private research dependency or frozen historical corpus. For implementation start at exact current PR stack, read related Issues, inspect worktree and existing tests/fixtures, then make a cohesive executable PR. A real incompatibility should be a pinned issue and explicit hold, not a silent conversion success. Do not merge/release or change owner-approved grammar without approval.

A good converter receipt states actual Rules/Tests converted and source feature families covered, validated schema SHA, emitted source IDs/hashes, loss/unsupported reasons, deterministic generation commands, downstream scanner execution status **not proved**, and remaining semantic decisions. Passing tests count only as secondary validation.
