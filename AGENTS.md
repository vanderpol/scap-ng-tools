# PERMANENT OWNER MANDATE — SCHEMA-FIRST, LOSSLESS SCAP 1.4 → SCAP-NG (2026-11-19)

**This is the converter project's controlling technical objective.** It supersedes any older content-first, sample-driven, blocker-count, historical-PR or conversion-percentage tasking below. It complements the owner-directed mainline integration policy (preserve tested work promptly, but never claim a release based on unproved conversions).

> **Engineer a deterministic, general translator that preserves the complete in-scope, nondeprecated SCAP 1.4 source language and semantics in the single active SCAP-NG 0.4.1 language.** A corpus-green conversion is an acceptance sample, **not** evidence that the language is covered.

## Normative sources, not benchmark content, define requirements

1. **Start from XML Schema, Schematron and normative semantics—not from STIG examples.** Enumerate the pinned original OVAL XSD inheritance/extension/restriction, imports/includes, substitution groups, abstract elements, choice/sequence, attributes, defaults, nillability, type constraints, and deprecations. Include embedded Schematron and documented evaluation semantics that XSD alone cannot express. Apply the same source-first method to XCCDF 1.2 (Rule, Group, Profile, Value, check-export, applicability), CPE, OCIL and SCAP datastream semantics. Enumerate separately by source dialect/version; legacy OVAL CPE 5.11.2 must not be assumed identical to OVAL 5.12.3.
2. **Authoritative OVAL pin:** `OVAL-Community/OVAL@2f140ee5c5dd1ed9606fcd5afc301f6baeb48706` (OVAL 5.12.3, 54 XSD files). [Canonical schema-first coverage Issue #80](https://github.com/vanderpol/scap-ng/issues/80) owns the source-language coverage gate. [Canonical PR #81](https://github.com/vanderpol/scap-ng/pull/81) introduces the read-only grammar inventory. It is a first-pass declaration inventory, **not** proof that every field, state, function or runtime contract is mapped. **Do not equate unmapped source declarations with confirmed defects:** classify official deprecations, scope and aliases first.
3. **Maintain a comprehensive normative source→native crosswalk.** For every in-scope nondeprecated Test/Object/State/Item family, field/attribute, option/default, type, behavior, nested Object Set/Filter, Variable source/function/composition, checks/cardinalities, logical operator, reference, status, Profile/applicability/Input construct: record the original QName/XSD pointer, Schematron/prose meaning, exact source revision, canonical JSON Schema pointer and semantic mapping, converter function, validation, RI obligation, and evidence. Source constructs absent from the 65 STIGs **still require a disposition**. Source metadata maps are *not* complete because a mapping file exists.
4. **Separate specification, representability, implementation and proof.** Explicitly classify each feature as native-representable / canonical-language gap / converter adapter gap / runtime-or-collector gap / deprecated (with official version, replacement and original source evidence) / source-invalid / owner-explicitly-excluded / not-yet-proved. The presence or absence of a collector does not determine whether the native grammar is expressive. Unknown or partially mapped cases are **holds**, never silently converted. Do not invent new deprecations or treat a deprecated alias as though every operation sharing its name is deprecated.
5. **Design general native semantics before recovering individual Rules.** Preserve all nondeprecated source behavior: nested and directional Sets, include/exclude Filters at the correct stage, dynamic Variable Objects and multiple/ordered values, expression composition, typed literals and explicit source-defined conversion, record-valued State fields, status and incomplete-population propagation, original defaults and cardinalities, Boolean grouping, XCCDF input/profile/applicability inheritance and evidence/provenance. Reuse approved generic native constructs; do not add per-benchmark fixes, hardcoded Values, fake Items, implicit casts, altered XML or invented manual fallbacks. If canonical 0.4.1 cannot express a valid in-scope source construct, create a minimal owner-reviewed canonical requirement and coordinate Tools, RI and VS Code instead of quietly dropping it.
6. **Generate conformance from normative source grammar.** For every distinct supported production, legal choice, enum/default, field/attribute, function and semantic boundary, generate minimal original-XSD/Schematron-valid positive and invalid negative witnesses plus independently specified expected outcomes. Use bounded pairwise/targeted partitions for combinations rather than claiming exhaustive enumeration of all XML documents. Test original XML validity, source AST fidelity, native JSON Schema + semantic validation, deterministic YAML/JSON, nested graph/reference integrity, explicit negative holds, and RI/SCC behavior where available. Never infer runtime equivalence from source parsing or schema-valid output.
7. **Use the signed 65-benchmark archive set and the standalone OVAL Self-Assertion corpus only for regression and real-world qualification.** Preserve all original Rule/Definition/Test IDs, hashes, source dialects and manifests; compare same-denominator status by source identity and full exact pinned provenance. A new Rule blocker is a sign of a previously untested *language-level* contract; root-cause the source grammar and crosswalk first, then write a reusable source-valid regression. Do not use corpus counts to decide what features are required.
8. **Do not declare the converter done merely because blocked Rules reach zero.** A release claim of “lossless for in-scope nondeprecated SCAP 1.4” requires 100% **accounted-for** source-language grammar (with transparent approved exclusions), zero silent semantic drops or unsupported source features falsely labeled converted, passing independently sourced conversion semantics, and separate runtime/RI parity status. Report distinct metrics for (a) language features specified/dispositioned, (b) native representability, (c) converter source parity, (d) complete benchmark/standalone source accounting, and (e) runtime execution equivalence. Current historical converted/blocked/manual counts are *diagnostics*, not this acceptance criterion.
9. **Guard the primary mission against context loss in every Codex session.** Before changing converter code, read **this mandate**, canonical #80, Tools [release #71](https://github.com/vanderpol/scap-ng-tools/issues/71), live 0.4.1 schema, actual head/CI and the coverage crosswalk. State which normative source rule is being implemented, native mapping, generic tests, schema/RI impact, and remaining language-level gaps in the issue/PR receipt. Do not pivot to single-Rule blocker chasing, a second converter, old 0.4.0 grammar, outdated pinned snapshots or content-specific hacks without documented owner approval.

**Priority when deciding work:** normative schema/semantic audit → native-language gap closure → generic deterministic converter → generated source conformance → full corpus regression → qualified downstream RI/editor content. The active canonical SCAP-NG authoring version is **0.4.1 only**. Historical 0.4.0 remains in Git archives and must not be used for new production authoring or new editor builds.

**Coordination:** Tools owns converter; canonical `scap-ng` owns language; RI owns execution; VS Code owns authoring. Do not interrupt current RI work to perform this schema-first converter audit; request a bounded checkpoint/pause only when the owner directs. Keep real outstanding PR integrations and release gates visible.

The owner prioritizes **preserving implemented pre-alpha work in `main`** over accumulating open draft PRs. `main` is the active **development** baseline, not a claim of product readiness. This overrides older instructions to keep all development draft-only; security, source/provenance checks, test honesty, canonical version coordination, and release gates still apply.

- **Default: commit tested, reviewable increments promptly to `main`**, or open a short-lived PR targeting `main` and merge it at the end of the bounded task. Do not leave an implementation PR indefinitely unmerged just because broader runtime qualification is outstanding; document those known holds separately.
- **Maximum one dependent PR above a main-targeted integration PR** (stack depth two). Exception only with an explicit owner-approved dependency and a named consolidation date. Never start another stacked implementation when current stacked work could be integrated.
- **Check existing work before coding:** inspect `main`, open PR bases/SHAs and previous implementation before implementing a feature. Reconcile rather than duplicate. Every implementation must have a pushed commit, visible PR/merge receipt, tests/results, and disposition of related older PRs.
- **Merge promptly; review debt every working session:** inventory open PRs; for any older than 3 days, decide merge, repair, or explicit supersession. Treat more than five unmerged implementation PRs in one repo as an integration stop signal, not permission to begin more work.
- **Preserve ancestry when consolidating:** prefer merge commits over squash for long preexisting stacks, so Git commit reachability demonstrates what is in `main`. Never close or delete a branch merely because a newer PR exists; first verify the exact work is reachable or consciously superseded, record the evidence in PR comments, and retain divergent fixes.
- **No false green:** failing CI, pinned schema mismatches, external equivalence holds, and missing real-execution receipts remain visible open defects. A pre-alpha merge can be owner-authorized with such holds; a release qualification cannot. Do not disable tests/checks or fabricate evidence to get the merge through.
- **No silent cross-repo drift:** after changing canonical language, propagate exact schema digests to converter, RI and VS Code as a separate tracked integration issue. Avoid ad hoc pinned snapshots or parallel active versions.

## Mandatory conversion semantics

- Convert SCAP 1.4 source Benchmark/Rule and standalone OVAL 5.12.3 to native SCAP-NG 0.4.1, preserving source XML/check/Definition/Test IDs, dependencies and provenance. Original Rule policy and Assessment testing are separate. Prefer automated OVAL when OVAL+OCIL coexist, retaining OCIL as nondefault manual alternative. OCIL-only Rules -> manual Assessment. Four SQLEXT-dependent SQL benchmarks' 209 Rules remain excluded by owner decision. Obsolete source constructs do not become fake native equivalents or disappear silently.
- Historical PR #62 reported **8,892 source Rules; 6,732 converted/unverified; 507 blocked; 1,653 manual-only**; **do not use these outdated numbers as a current release status or as the target language's scope**. These are authoring/conversion counts, not scanner or SCC equivalence. Record independently validated outputs, semantic holds and all blocked reasons separately. Reconcile versioned old/new ledger and never promote schema validity into runtime proof.
- Preserve actual Variables, ordered multivalues, nested `concat`, `unique`, `merge`, `count` and source object/field references; no declaration-level datatype in approved native Variables, no coercion of numeric-looking source strings. Source expressions `foreach`, `else_if`, `values`, `regex_capture`, Set/Filter and arithmetic/legacy forms must map only when approved native semantics truly cover them; else explicit hold with source pointers. Do not silently discard entire source Tests or replace source collection with manual procedure without review.
- Real **CPE/platform applicability and shared applicability Assessments** must be converted as executable authored resources and correctly referenced by Rules/Benchmarks; no empty catalogs or hardcoded fixtures claimed as working. Profiles: Rules enabled by default, allow profile disable/re-enable. Preserve remediation, original Rule XML, input bindings, manual responses and publisher metadata.
- Full-65 corpus generation must be a **deterministic runnable script**, not repeated long AI editing sessions. Pin source ZIP/SHA and exact canonical converter/pack revisions; repeat generation and compare hashes. Large artifacts belong in evidence/Actions artifacts, not bloated commits. Validate JSON/YAML and produce per-Benchmark reproducibility receipts. Never silently update production content because schema changed.
- Maintain a clean audit of source->native edge cases and independent source test expectations (e.g. 0.3 304-vector historical evidence where relevant, without importing 0.3 grammar). Changed canon requires coordinated docs/metadata/pins, not a converter-only workaround.
